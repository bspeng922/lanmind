# 密码库内置插件

密码库（`vault`）随桌面应用编译发布，可在“设置 → 功能与插件”启停。它是本机当前身份的个人库，跨工作区使用，独立主密码解锁；不会加入任务、Wiki、AI、MCP、普通工作区同步或现有的数据清理。

开发者可从 [插件开发教程](plugin-development.md) 按步骤了解本插件的清单、前端入口、原生接口及宿主接入方式；通用约束见 [内置功能与插件开发规范](feature-modules.md)。

## 使用

首次进入创建至少 12 字符的主密码。主密码不能找回。支持登录密码及 OpenSSH Ed25519/RSA 密钥，支持生成 Ed25519 密钥、多级文件夹、收藏、搜索、克隆、批量移动和回收站。回收站记录保留 30 天，在下次解锁访问时清理；删除文件夹默认将记录移到未分类。

密码生成器默认 20 位，支持 4–128 位、大小写、数字、ASCII 特殊字符和排除 `0 O o 1 I l`。每个启用类别至少出现一次，使用操作系统随机源和拒绝采样。

闲置默认 5 分钟锁定，可设 1/5/15/30/60 分钟。应用锁定、工作区切换、停用插件及系统恢复后也会锁定。未保存的编辑会被丢弃，没有明文草稿。复制的敏感内容 30 秒后按所有权清理，锁定时提前清理；不保证清除操作系统剪贴板历史。

## 存储和接口

数据放在应用数据目录 `vault/<本机用户ID的SHA-256>.sqlite`。SQLite 存储版本化头部和一个整体加密的数据快照，快照包含记录、文件夹、设置与分享私钥。每次变更重新加密快照，通过事务一起更新密文和版本；记录另有乐观并发版本。只在内存中解密内容，列表移除密码、私钥、私钥口令、备注和公钥，备注搜索在后端解锁会话中完成。库容量上限为 32 MiB 明文载荷、20,000 条记录及 5,000 个文件夹。

主密码使用 Argon2id（64 MiB、3 次迭代、并行度 1、16 字节随机盐）派生包装密钥，包装随机的 256 位库密钥。包装和数据均使用 XChaCha20-Poly1305、随机 24 字节 nonce 和身份/版本绑定的认证数据。主密码变更只更新包装头部。密钥、解密字节及整体数据快照使用 `zeroize` 容器管理；前端必要的编辑明文由会话边界卸载，不声明 JavaScript 内存可可靠清零。

`vault_api({ action, payload, sessionVersion })` 只接受主窗口调用。初始化、解锁、锁定和状态查询有独立入口，业务动作必须匹配当前解锁会话版本，并检查应用锁及插件状态。敏感结果若跨越锁定版本，前端客户端会丢弃。`vault://state` 和 `vault://changed` 只广播状态及版本，不包含凭据。

前端代码及中英文资源位于 `lanmind/plugins/password-vault/`，原生代码位于 `lanmind/src-tauri/src/vault/`。清单使用完整 `vault:` 翻译键，宿主兼容原有短翻译键。

## 备份和导入

- 原生 `.lmvault` 加密备份保存记录、文件夹、回收站和设置，使用独立的至少 12 字符备份密码。恢复时创建新记录 ID 并以目标库密钥重新加密，不恢复设备身份和分享私钥。
- Bitwarden 明文 JSON 支持登录项和文件夹；其他类型、TOTP、自定义字段及附件会在预览中报告。文件夹导出为路径名称，不支持的扩展字段不承诺往返保留。
- CSV 支持名称、网址、用户名、密码、备注、文件夹列映射，正确处理引号、逗号及换行；只保存登录项和第一个网址。SSH 私钥使用原生备份或独立 OpenSSH 导出。
- 导入文件最大 64 MiB，密码库解密内容最大 32 MiB（加密备份的 Base64 封装会增加文件体积）。导入前展示预览，确认时重新核对文件摘要；默认跳过重复项，可改为追加，不覆盖原记录。文件夹按路径合并，写入失败事务回滚。
- 明文导出和 SSH 私钥导出必须再次验证主密码。导出只创建新文件，不覆盖已有文件；原生备份默认包含回收站，明文格式排除回收站。

## 聊天分享

只支持当前工作区的一对一分享，默认站点、账号和名称，密码需主动勾选；SSH 只分享公钥和指纹。分享是快照，对方保存后拥有独立记录，不提供撤回、严格一次查看或阅后即焚。

每个密码库生成独立 X25519 分享密钥。公钥证明由现有设备 Ed25519 身份签名，指纹须与接收人核验。通过独立、签名且使用现有工作区加密通道的查询请求获得公钥，不修改 UDP 发现协议。首次接收需要对方初始化密码库；核验并发送后缓存其签名公钥，支持后续离线交付。在线密钥变化必须重新核验。

凭据快照使用临时 X25519、HKDF-SHA256 和 XChaCha20-Poly1305 接收者加密，并绑定工作区、发送者、接收者、分享 ID 与密钥版本，信封再由发送设备签名。现有聊天类型增加 `vault_share`，内容只存密文信封。聊天预览和通知只显示通用文案，禁止普通转发、复制正文或转任务，聊天搜索跳过这些信封。解密在密码库页面进行，重复保存通过分享 ID 拒绝。

旧客户端的普通任务同步继续兼容；不支持公钥查询的客户端不能作为分享接收端。接收端插件关闭时只接收并保存聊天密文。重建密码库后旧分享密钥失效，旧分享无法恢复，已导入的记录以备份为准。

## 验证

在 `lanmind` 下运行 `npm run lint`、`npm run check:i18n`、`npx tsx --test plugins/password-vault/client/client.test.ts`、`npx playwright test tests/theme/vault.spec.ts tests/theme/features.spec.ts`、`npm run build`；在 `src-tauri` 下运行 `cargo test --lib`。

Rust 测试验证加密落盘、错误密码、篡改拒绝、会话锁定、版本冲突、文件夹、生成器、SSH、备份/CSV/Bitwarden 导入及签名分享。浏览器测试使用显式内存传输测试界面交互，不代替原生加密或真实桌面设备间的手动验收。
