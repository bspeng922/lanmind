# 内置功能与插件开发规范

LanMind 使用任务核心、内置业务模块和预装插件三层结构。任务、项目、工作区、成员、权限及任务同步属于核心；Chat、AI、Wiki 属于内置模块；Optical Transfer 和 Password Vault 属于预装插件。密码库的数据边界、加密协议及开发接口见 [密码管理插件](password-vault.md)。

本版的插件随应用编译、发布和更新，支持独立启停。尚不提供外部包导入、独立二进制更新、在线市场或第三方代码沙箱。插件清单中的版本描述插件契约版本，不能用于宣称可单独更新 Rust 代码。

首次开发请阅读 [插件开发教程：以 Password Vault 为例](plugin-development.md)。教程包含真实目录与清单解析、可复制的 Hello 插件、前后端注册位置、国际化、启停清理和交付检查。第三方目前通过源码集成并重新构建宿主发布插件。

## 注册和边界

- 内置模块注册在 `lanmind/src/modules/catalog.json`，声明 ID、版本、导航段、视图、设置页及原生命令。核心任务接口不得归属可选模块。
- 插件放在 `lanmind/plugins/<name>/`，提供 `manifest.json`、前端入口及自己的语言资源。`plugins/optical-transfer` 是首个实例，复用原有光学业务源码和原生实现，保留原有缓存路径及离线接收器。
- `src/modules/views.tsx` 提供统一的延迟加载和启停边界；导航及设置根据注册表和状态显示。新增业务页面应通过此边界加载。
- 原生命令由 Rust 调用分发器按同一注册表检查；共享命令通过参数选择业务时，必须在实际业务入口再调用 `require_feature`。不得只依赖隐藏按钮实现停用。
- 跨模块能力通过明确的服务适配器调用，例如 Wiki 的 `wikiPolishClient`。可选依赖关闭后，应停用关联操作；模块主体保持可用。

## 状态和生命周期

- 默认启用全部现有功能。开关保存于本机数据库的应用级 `featureModulesV1` 设置，不进入同步记录，对所有工作区生效。
- 查询接口为 `get_feature_modules`，修改接口为 `set_feature_module_enabled({ id, enabled })`。修改时检查应用锁，成功后广播 `features://changed`。
- 各桌面窗口先调用 `initializeFeatures`，界面使用 `useFeatures` 订阅；浏览器开发环境使用独立的 localStorage 偏好及 storage 事件，不代表桌面持久化实现。
- 停用后撤销业务入口并卸载相应界面，释放事件、Worker、媒体、文件及其他资源；已保存数据和配置保留。重新启用恢复原有数据。
- Chat 停用后停止其操作收发和消息提醒，清理未读托盘；任务同步和任务通知继续运行。停用期间的聊天操作不会记录为已应用，可在重新启用并与持有历史的设备同步时补齐。
- AI 停用后取消 Agent、润色和旧模型请求，禁止调度器启动新任务。重新启用沿用现有调度规则处理到期任务，不为停用期间每个周期逐次补跑。
- Wiki 停用后关闭编辑界面，拒绝业务接口及分享路由，撤销其 MCP 工具。编辑器未提交草稿仍保留在原有恢复缓存；停用前正在执行的保存若被拒绝，不得清除草稿。
- Optical Transfer 停用后销毁独立窗口，卸载嵌入页面，停止摄像头和传输控制器，释放源文件引用并清理未完成输出；恢复缓存保留。已导出的独立离线接收器继续独立运行。
- Password Vault 停用后锁定原生会话，清理仍由密码库持有的剪贴板内容，并卸载包含解密数据的界面；加密库保留。重新启用后须再次解锁。

## 国际化和界面

- 每个模块维护自己的翻译命名空间。插件在清单声明 `namespace`、`defaultLocale`、`locales`，资源随源码发布，无需运行时联网获取。
- 官方插件必须提供 `zh-CN`、`en-US`，翻译键和插值参数一致。其他宿主语言按清单默认语言回退；避免覆盖宿主或其他插件命名空间。
- `npm run check:i18n` 会生成前端资源并校验宿主与插件翻译；Rust 构建也从清单收集相同资源。提交更新后的 `src/i18n/resources.ts`。
- 使用宿主主题变量和可访问的控件，支持亮暗主题、语言切换和键盘操作。React Portal 菜单严格遵守根目录 AGENTS.md 的定位规则。
- 用户生成的任务、消息及文档保持原文，错误使用稳定错误码。`FEATURE_DISABLED:<id>` 由宿主翻译为停用提示。

## 验证和扩展

新增或调整模块时验证：启停及重启持久化、工作区隔离、活动资源清理、停用接口拒绝、可选依赖、任务核心不受影响、中英文及跨窗口同步。原生业务行为使用 Rust 测试，界面与键盘交互使用 Playwright。

当前局域网传输与业务数据格式保持兼容，开关属于本机偏好，不强制改变其他设备的配置。外部插件包导入需要另行增加宿主资源加载、后台隔离、签名、权限和升级协议，不能仅凭修改清单支持动态执行代码。
