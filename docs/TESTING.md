# 测试手册

## 自动化检查

在 `lanmind/` 目录执行：

首次运行含 Playwright 的命令（如 `test:ai-questions`）前，执行 `npx playwright install chromium` 安装测试浏览器。

```bash
npm test        # 前端单元测试（任务、主题、工作区上下文与 AI 会话状态等）
npm run lint    # TypeScript 类型检查 (tsc --noEmit)
npm run check:i18n # 语言目录、翻译键与插值参数校验
npm run test:i18n  # 语言匹配、系统提示、日期显示与双语速记
npm run test:task-content # 任务 Markdown、链接与副本
npm run test:ai-questions # AI 追问解析、分组选择、文字提交和回答历史（含浏览器用例）
npm run test:optical # 光学传输核心与容量
npm run build   # 前端生产打包 (vite build)

cd src-tauri
cargo check     # Rust 语法与原生依赖检查
cargo test --lib # Rust 数据层、工作区隔离、P2P、MCP 与 AI；原生环境用例有默认跳过项
```

`npx playwright test tests/theme/i18n.spec.ts` 验证中英文即时切换、刷新保留、浏览器标签页同步、英文设置导航及下拉菜单、小窗口和独立窗口。桌面端还需检查切换后的托盘菜单、窗口标题，以及显示器工作区内的通知与速记窗口；用户输入和已生成的报告应保持原文。

协作项目工具栏、任务动态和同步日志分页可运行 `npx playwright test tests/theme/project-layout.spec.ts tests/theme/log-pagination.spec.ts tests/theme/network.spec.ts`。分页用例覆盖每页 20 条、末页、刷新、新记录进入时的翻页稳定性、读取失败重试以及浅色/深色窄屏布局。Rust 用例同时验证超过 5,000 条任务历史仍能完整浏览，且每次读取任务动态都检查当前权限。

`npx playwright test tests/theme/ui-refinements.spec.ts` 覆盖筛选下拉框越过面板边界且不增加面板滚动范围、密集任务的紧凑日历、子任务只在父任务下展开、更多菜单点击外部关闭、项目标题栏任务数量与图标新建入口，以及重开设置后显示访问密码。任务总数和已完成数量均排除子任务。

任务列表的展开箭头同时支持独立子任务和检查事项，两者分段显示；勾选检查事项应同步 Markdown，网络只读模式仅允许展开查看。`npx playwright test tests/theme/task-detail.spec.ts tests/theme/network.spec.ts` 还覆盖标签已选/可选顺序、＋输入后回车创建、×/空白/Escape 取消、网络日历在缩放后仍显示“查看全部”、以及完整任务副本的父子关联。副本保留正文、标签、附件和排期，将主任务与子任务的状态、进度、检查事项重置为待办；评论与历史仍属于原任务。`npm run test:task-content` 验证副本使用新 ID、图片引用仍可解析、原任务不被修改，Rust 数据层同时检查子任务标签与提醒时间不会在保存时丢失。

当前开发版新增交互可在 `lanmind/` 运行以下定向回归：

```bash
npx playwright test tests/theme/task-cards.spec.ts tests/theme/task-deletion.spec.ts tests/theme/task-editor-layout.spec.ts tests/theme/ai-questions.spec.ts tests/theme/wiki-history.spec.ts
```

这些用例覆盖亮暗主题和不同宽度下的卡片字段、密度偏好、只读展开、删除取消与失败重试、保留/删除子任务、编辑器焦点与属性切换，以及 Wiki 历史、自动保存和恢复草稿。新建表单最大宽度为 820px，窄屏仍需完整执行排版与下拉菜单边界检查。Wiki 创建顶层页面时先打开“New page options”菜单，再选择“New top-level page”；选中页面时直接点击新建主按钮会创建子页面。

AI 追问用例同时验证多项文本追问合并提交，原问题和完整回答可回看，文本标记不会执行工具。Rust 定向回归可在 `lanmind/src-tauri/` 执行 `cargo test --locked --lib collaborator_personal_state_survives_unrelated_task_updates` 和 `cargo test --locked --lib moving_personal_task_to_project_resolves_a_project_state`，分别验证协作者自定义状态在后续编辑中保留，以及移动项目后的状态归属。

网络伺服访问密码右侧按钮顺序为查看、复制、随机生成。复制已保存但隐藏的密码时不得修改配置或强制显示明文；复制失败或旧版只有哈希的密码应给出提示，不能显示复制成功。

网络伺服密码还需在桌面端验证：设置密码并等待自动保存，退出并重新启动应用，再点击眼睛查看原密码；只切换显示或隐藏不得修改配置。Windows 使用当前用户的 DPAPI 加密保存，其他桌面平台使用应用数据目录中的私有密钥；明文只通过主窗口的专用命令读取，网络状态和任务导出不包含密码。旧版只有密码哈希的配置需重新设置一次密码才能查看，点击眼睛应提示这一限制并保留原密码。Rust 测试验证加密值持久化后能够读取、篡改被拒绝以及配置修改不丢失密码数据。

Rust 测试覆盖空库初始化、旧演示数据迁移、任务 CRUD、项目加入审批、按成员过滤同步操作、同步幂等和加密文件分块。

`npm run dev` 只适合检查浏览器渲染效果。涉及 SQLite、P2P、托盘、通知、文件传输和全局快捷键的用例必须在 `npm run desktop`（Windows）或 `npm run desktop:unix`（macOS/Linux）下验证。

## 桌面回归

任务筛选支持优先级、状态、截止/排期日期、标签、负责人和个人范围的项目多选，同一维度取“或”、不同维度取“且”。个人范围和各项目独立保存条件，列表、日历、时间线、看板共用偏好。执行 `npx playwright test tests/theme/task-multi-filters.spec.ts tests/theme/calendar-filters.spec.ts tests/theme/timeline.spec.ts tests/theme/project-layout.spec.ts tests/theme/network.spec.ts` 验证连续多选、旧偏好恢复、日历循环排期、列内/日内/任务行排序、跨日刷新及网络只读行为；`npm test` 包含组合筛选和排序的单元测试。

执行 `npm run desktop` 后检查：

1. 首次启动只有本机用户，项目、任务、节点和同步日志均为空。
2. 打开“新建任务”，持续输入并等待超过 10 秒，标题和描述不得被轮询清空；保存后任务应立即出现。
3. “系统设置 → 基础配置 → 常规 → 关闭按钮行为”默认选择“最小化到系统托盘”。分别最小化主窗口、点击关闭按钮隐藏主窗口；两种情况下单击托盘图标都可恢复主界面，托盘图标右键选择“显示主界面”仍可恢复。改为“退出程序”后，关闭主窗口应结束整个进程（包括托盘和附属窗口）；重新启动应保留该选择。改回托盘选项并重启，关闭主窗口仍应隐藏到托盘。原生关闭操作（如 Alt+F4）和锁定界面关闭按钮同样遵循该设置，关闭附属窗口不应退出程序。
4. 窗口隐藏后按快速创建的系统快捷键，窗口恢复并打开快速创建对话框。
5. 修改快捷键并保存，立即验证新组合；尝试已被其他程序占用的组合时应显示错误且不写入本机配置。
6. 在“系统设置 → 界面主题配色”启用“跟随系统”，切换 Windows 浅色和深色模式，主题应分别实时切换为“亮色”和“暗色”。验证旧五套主题设置自动映射到亮/暗主题，重启与附属窗口保持一致。
7. 在“系统设置 → 基础配置”启用开机自动启动，确认系统登录后 LanMind 静默进入托盘且不弹出主窗口；关闭设置后确认启动项被移除。
8. 在设置的独立“数据导出”面板导出任务，再从“数据导入”面板导入同一文件，应显示当前工作区的重复任务被跳过；跨工作区导入应重映射冲突 ID，不能覆盖其他区记录。导入缺少可用项目或成员的归档时，任务应转为当前用户的个人任务并立即出现在任务列表；模板下载、原生另存为和失败提示均须可用。
9. 托盘图标右键选择“退出智域协同”，进程应结束。
10. 创建两个项目用户，未审批用户不能读取或创建项目任务，项目管理员批准后才可访问。
11. 在全员广播发送消息，两端都只能在“全员广播频道”看到，不得混入发送者的单聊。
12. 在单聊中让双方各发送一条消息，清空当前对话后本机两条都消失；对方节点的记录必须保留。
13. 关闭一个节点后，其他节点应保留该用户并显示离线；已有任务的指派人信息不得丢失。
14. 修改节点名称或头像，执行同步后其他在线节点应更新显示。
15. 开启桌面日历，分别在浅色和深色主题设置背景为 0%、25%、90%；0% 的空白日期格应直接显示壁纸，其他数值只改变底色，文字不应一起变透明。
16. 连续切换锁定/解锁至少 10 次，解锁后拖动标题区、拖动八个方向的缩放边缘；只应存在一个日历窗口，旧位置不得残留黑底或系统标题栏，主窗口与托盘仍应响应。
17. 锁定后拖动标题区和边缘不得改变位置大小；其他应用应盖住日历，按 Win+D 后应仍可看到日历。退出并重新启动，日历位置、大小和透明度应恢复。
18. 锁定时双击日期，验证备忘表单能输入文字；关闭表单后日历应回到底层。关闭日历后桌面不得有残留，再从托盘开启应恢复正常。
    - Windows 可运行原生回归测试：`cargo test --lib desktop_calendar::windows::tests::show_desktop_keeps_calendar_above_icon_host -- --ignored --test-threads=1`。测试会暂时切换系统“显示桌面”，验证日历层级、焦点及顶层窗口属性，并恢复桌面状态。
19. **macOS 专用回归**：
    - 验证主窗口左上角经典“红绿灯”控制按钮（关闭、最小化、最大化）均能正常响应，右侧无多余 Windows 控制方块；
    - 全局搜索栏应显示 `⌘ K` 快捷键徽标；
    - 快捷键设置弹窗应提示 `⌘ / ⌥ / ⇧`，且录制 `Command` 键时能正确识别并展示 `⌘` 字符；
    - 桌面透明日历窗口应深度置于桌面壁纸层，切换不同桌面空间（Mission Control / Spaces）时日历保持常驻。
20. **Linux 专用回归**：
    - 验证桌面日历窗口置底并跳过任务栏；
    - 验证 `.deb` 安装包或 `.AppImage` 独立运行正常。

## 聊天截图

- 聊天工具栏的顺序应为表情、图片、传输文件、截图、截图下拉箭头；浅色、深色和英文界面都应显示正确。
- 在桌面客户端点击截图，在聊天窗口所在的屏幕拖动框选；Enter、双击选区或复制图标应直接将图片写入系统剪贴板并退出截图，不再打开发送预览。图片应能粘贴到聊天输入框和其他应用。
- 下载图标应打开系统“另存为”对话框，确认后保存为 PNG 并退出截图；取消保存或写入失败时保留选区供重试。
- 在聊天输入框按 Ctrl+V 粘贴剪贴板图片，应显示待发送缩略图并保留文字草稿；可移除图片、单独发送图片或和文字一起发送，失败时保留未发送图片。
- 从截图箭头菜单选择“隐藏窗口截图”，主窗口应在捕获屏幕前隐藏；截图完成、Esc/右键取消、关闭截图窗口或截图失败后均应恢复主窗口。普通截图应包含原本可见的主窗口。
- 在 100%、150%、200% 缩放下检查截图区域与实际图片一致；取消不应新增消息，只读项目会话应禁用截图。截图下拉箭头应和截图图标紧邻，呈按钮组形式。
- macOS 首次截图可能需要在系统设置中授予屏幕录制权限；Linux 需要桌面会话，Wayland 支持取决于桌面提供的截图接口。
- 自动验证：`npx playwright test tests/theme/screenshot.spec.ts` 检查按钮组、菜单、框选坐标、复制/另存为操作和图片粘贴发送；`cargo test --lib screenshot::tests` 检查原生裁剪、PNG 编码与保存。图形桌面下可运行 `cargo test --lib screenshot::tests::native_screen_capture -- --ignored` 验证原生屏幕捕获，或 `cargo test --lib screenshot::tests::native_clipboard_roundtrip -- --ignored` 验证系统图片剪贴板。

## 程序自动锁定

- “系统设置 → 基础配置 → 常规 → 自动锁定界面”默认关闭，可设置 1–1440 分钟无操作后锁定，以及 8–128 个字符的独立解锁密码，点击“保存锁定设置”生效。
- 启用后重新启动需要解锁。修改设置、关闭自动锁定、更换密码或清除密码须在独立弹窗中验证当前密码；错误密码、取消或 Escape 不得修改已保存的设置。清除密码同时关闭自动锁定，重新启动后保持清除状态，也可重新设置密码。密码仅以加盐 Argon2 哈希保存在本机数据库，不随任务导出或局域网同步。
- 活动计时涵盖程序窗口内的鼠标、键盘、输入法输入和滚动操作；缩到托盘仍继续计时，后台同步与网络伺服继续运行。
- 手动验收：设为 1 分钟，打开任务编辑器并填写未保存内容，停止操作后等待锁定。按 Escape 或输入错误密码应保持锁定；正确解锁后编辑器与草稿应保留。继续操作应重新计时。
- 开启桌面日历、快捷新增或光学传输窗口后锁定程序，附属窗口应隐藏；Win+D 不应恢复任务内容，解锁后恢复此前窗口。从托盘或快捷键打开程序仍须解锁。
- 确认任务列表没有六点拖动图标，编辑、置顶、子任务展开及更多菜单仍可使用。
- 自动验证：`cargo test --lib` 包含锁定计时、过期首个输入、防止旧状态覆盖、密码验证、配置保存失败与数据库重开测试；`playwright test tests/theme/app-lock.spec.ts` 验证设置、输入活动、锁屏、门户下拉菜单保护、草稿保留及浅色/深色主题（浏览器使用 IPC 模拟，托盘和 Win+D 按上面的步骤验收）。
- 启动时先显示原有 Logo、名称与加载动画，开屏至少显示约 650 毫秒，覆盖锁定状态与本机身份读取过程；最终界面绘制完成后直接切到主界面或解锁面板，中间不显示“正在读取锁定状态”卡片。开机静默托盘启动保持静默。首次读取遇到短暂错误时继续显示开屏并自动重试，不能暴露任务内容；持续失败超过 5 秒退出开屏并显示受保护的错误与重新读取按钮。取得有效状态后再发生读取失败仍须立即遮蔽界面。
- `playwright test tests/theme/app-startup.spec.ts tests/theme/app-lock.spec.ts` 验证真实开屏 HTML 与样式覆盖锁定遮罩、快慢启动的显示时长、锁定与身份以不同顺序完成、StrictMode 下窗口只显示一次、启动直接解锁、短暂错误恢复及持续失败后的可重试状态，包含深浅主题截图；窗口显示调用由模拟记录，真实窗口显示与开机托盘启动仍须在 Windows 中验收。
- 常规设置顺序：开机自动启动、关闭按钮行为、侧边栏显示未完成数量、显示农历与节气、每周第一天、休息日、自动锁定界面。设置与确认解锁密码应并排；当前密码只在验证弹窗中输入。
- `playwright test tests/theme/window-close.spec.ts` 验证关闭按钮行为的默认值、两个选项、重启读取、读写失败重试及深浅主题；`cargo test --lib close_button_behavior` 验证本机配置默认值、未知值兼容与数据库重开后的持久化。真实托盘和退出行为按桌面回归第 3 项验收。
- 网络伺服登录页应适配深浅主题与窄屏，密码可显示/隐藏，错误密码可修正后重新提交。任务编辑页与只读信息页的评论使用统一样式，显示昵称、头像、时间及 Markdown，发表评论和删除自己的评论后应立即更新；他人的评论与只读页面不显示删除操作。
- 评论支持一层引用回复：选择评论后在输入区显示作者与正文摘录，取消引用保留已输入正文；发送失败保留正文及引用，可继续重试。已发送引用可点击跳回原评论，原评论删除后保留快照并提示不可用。引用回复不嵌套整个历史，普通正文继续支持 Markdown。
- 引用由服务端按同任务评论 ID 生成，不能引用不存在、已删除或其他任务的评论，客户端不得伪造作者及引用快照；网络只读模式可查看引用并跳转，不提供发表、回复或删除按钮。旧评论无引用字段仍可读取，新引用随局域网同步和数据库保存，原评论修改或删除不会改写已发送的引用。
- `playwright test tests/theme/task-detail.spec.ts tests/theme/network.spec.ts` 验证引用选择、取消、跳转、删除原文后的快照、失败重试及 HTTP 参数；`cargo test --lib` 验证同任务约束、服务端快照、旧数据兼容、数据库重开和局域网同步。

## 双节点网络检查

1. 两台设备连接同一局域网，并将网络设为互信的局域网/专用网络。
2. 允许 LanMind 通过系统防火墙的局域网通信端口（UDP 45991 及动态 TCP 端口）。
3. 确认网络未启用访客隔离、AP 客户端隔离或阻断 UDP 广播/组播。
4. 启动两端后等待至少 10 秒，节点应互相出现；退出一端后对方应将其标记为离线，而不是删除。
5. 分别验证广播、单聊、项目成员审批、项目任务和图片/文件传输。

- 自动检查：`cargo test --lib shared_files` 验证真实临时文件、加密 TCP 回环、权限撤销、断线清理、路径越界、源文件变化、同名文件保护、分块下载、续传及多层目录和空目录保留。`npx playwright test tests/theme/shared-files.spec.ts` 验证入口、目录树按需展开、只读/可写操作、停止共享及英文窄窗口；界面用例使用模拟服务。

- A 默认只读时，B 不得上传或创建目录；A 改成可写后，B 可以上传新文件、创建目录；重复上传同名文件应报错且原文件不变。A 停止共享或改回只读后，B 的后续请求和未提交上传应失效。
- 验证下载进度、取消、断网、重试续传、共享者离线、源文件变化、磁盘空间不足及旧客户端。A/B 切换工作区后，原上下文的操作不得继续访问或写入其他工作区。Windows 共享目录句柄阻止移动/替换目录，停止共享后应释放句柄。
